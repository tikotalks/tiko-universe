# Tiko Write — native iOS handwriting app on a Kotlin stroke engine

## Context

Sil's son uses **Writing Wizard** (`id1305242235`), plus its two siblings **Cursive Letters Writing Wizard** (`id1412628587`) and **Writing Wizard School Ed.** (`id631446426`). Between them they cover print letters, cursive with letter joins, numbers, shapes, custom word lists, 16 handwriting fonts, per-child profiles, progress reports, and school/MDM deployment — behind a $9.99 paywall, three separate apps, and a busy interface full of stickers, mini-games and score screens.

Tiko Write replaces all three with **one free, calm, fully native app**. The teaching content is not code: every glyph is authored SVG stroke data, versioned in git and editable in the Tiko admin, so a new handwriting style or alphabet is a content change, not a release.

The tracing engine is written in **Kotlin Multiplatform** behind a product-neutral boundary, so the same validated logic serves iOS now, native Android later, and the admin's authoring preview via `wasmJs`. This follows the precedent already accepted in `docs/adrs/2026-07-01-tiko-chess-and-mazzi-engine-boundary.md`: engines are product-neutral modules consumed through a narrow API, and Tiko owns pedagogy, copy, voice, and Parent Mode — never engine internals.

Write is also the **proof app for `TikoKotlinKit`** — a shared Kotlin logic layer that will, over time, take identity, i18n, and API clients out of TikoKit so TikoKit becomes purely UI. That migration is deliberately staged behind Write's release rather than bundled into it: `TikoIdentity.swift` is 739 lines of Keychain, device bootstrap and session handling relied on by eleven shipped apps, and rewriting it is the single riskiest change available in this repo. Doctrine already answers how to sequence it — *build one proof app before broad migration*, and *deletion requires proof: inventory, replacement, tests, smoke evidence*. So v1 stands up the toolchain, the framework pipeline and the lowest-risk tier; the auth layer moves after Write ships, under its own ADR.

**v1 is iOS only.** No web client, matching `say`, `sum`, and `first`, which are already iOS-only apps in this repo.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Name | **Write** | Chosen by Sil. Covers tracing, letters, numbers, shapes, and later free writing. |
| App key / bundle | `write` / `mt.tiko.write`, scheme `TikoWrite` | Matches every other Tiko iOS app. |
| App colour | `0x22c55e` green, dark `0x11622f` | Only unclaimed hue in `TikoAppColor`; distinct from Type/Radio orange and Say violet. |
| Clients | iOS only in v1 | Sil's call. Engine is portable, so Android is a UI project, not a rewrite. |
| Kotlin/Swift seam | **Logic in Kotlin, everything device-touching in Swift** | Geometry, state machines, contracts and data are portable. Rendering, gestures, audio, speech recognition and SwiftUI are not. |
| Engine location | `engines/stroke/`, public API `StrokeCore` | Product-neutral naming per the chess ADR. It traces arbitrary paths; it knows nothing about Tiko. |
| Shared logic layer | `packages/tikokotlinkit/`, public API `TikoKotlinKit` | Tiko-branded shared logic, separate module from the neutral engine. Grows tier by tier; TikoKit shrinks to UI. |
| iOS packaging | One `TikoCore.xcframework` exporting both modules | Kotlin/Native embeds its runtime per framework; two frameworks would double binary size and risk duplicate-class issues. Publishing StrokeCore standalone later is a Gradle target addition, not a restructure. |
| Migration scope in v1 | Tier 0 only (~297 lines of genuinely pure logic). No existing app touched. | Proves the toolchain end to end without betting an App Store release on a rewritten auth layer. |
| Glyph source | `packages/write-glyphs` in git → seeded to D1 → served by content-api → overridable in admin | Mirrors `packages/talk-packs` + the Cards/Sequence defaults pattern. App works offline from a bundled copy; changes are reviewable in git. |
| v1 content | Shapes, numbers 0–9, print A–Z/a–z | Shapes prove the engine cheaply, numbers are near-free, print letters are the product. |
| Cursive | Phase 6 | Needs entry/exit anchors and join geometry — a real data-model and engine extension, not a content addition. |
| Monetisation | None. Free, no IAP, no ads | Doctrine. |
| Licensing | `engines/stroke` and `packages/write-glyphs` structured as independently licensable (own `LICENSE`, no Tiko imports); repo-wide open-source call deferred to release | The monorepo is `private: true` with no LICENSE and holds worker configs. Extraction stays a packaging move, per the chess ADR. |

### Taken from the three source apps

Stroke-order teaching with ordered key points · directional validation · the three off-path recovery behaviours · animated model demonstration with speed control · letter name vs. phonics vs. letter sound · left-handed mode · letter size · guide lines · Apple Pencil support incl. Pencil-only mode · parent-protected settings · per-child profiles · replayable tracings for parents · the five-attempt fading-help ladder.

### Deliberately dropped

16 handwriting fonts (ship one Tiko print, later one Tiko cursive) · paywall and IAP · 50+ stickers · five mini-games · star **scores**, timers, streaks and leaderboards · MDM remote configuration · three separate apps.

The five-attempt ladder is kept as **pedagogy, not scoring**: each attempt removes help (full model → faint model → start dot only → key points only → nothing). Shown as five filling dots, never a score. Accuracy is measured but surfaced only in Parent Mode. No app-visible "wrong".

## Architecture

```txt
KOTLIN  engines/stroke/ + packages/tikokotlinkit/  →  TikoCore.xcframework
  :stroke-core     (product-neutral)
  • SVG `d` parser → adaptively flattened polyline
  • arc-length table: pointAt(s), tangentAt(s), closestPoint(p)
  • key point generation (curvature extrema + spacing) and ordering
  • tracing state machine: corridor hit-test, direction, frontier, lift rules
  • off-path policies, difficulty resolution, 5-attempt ladder, accuracy scoring
  • glyph pack decode (kotlinx-serialization) + pack schema version checks
  → returns semantic tags. Zero prose, zero platform deps, zero Tiko concepts.

  :tikokotlinkit   (Tiko-branded shared logic — v1 ships Tier 0 only)
  • TikoImageURL, TikoWordMatcher, TikoMediaQuery, TikoVersionCheck
  • later tiers: i18n resolution, identity + API clients (see migration ladder)

SWIFT   apps/write/ios/
  • touch + Pencil capture (coalesced touches, force, tilt), CoreGraphics ink
  • model demo animation, key point pops, ink snapping, Reduce Motion paths
  • TikoVoice (letter name / phonics / sound), TikoFeedback haptics, TikoCelebrate
  • TikoAppShell, TikoI18nWrite, Parent Mode + PIN gate, TikoIdentity
  • content fetch, UserDefaults-per-subject store, app-api state sync

TYPESCRIPT
  • packages/write-glyphs — authored stroke JSON, source of truth
  • workers/content-api — /v1/write/content (defaults + per-account overrides)
  • apps/admin/web — WriteEditor.vue stroke authoring + useWriteDefaults.ts
```

The engine is the **single source of geometry**. Swift does not parse SVG: it asks `StrokeCore` for the flattened polyline and builds its `CGPath` from that. The path drawn on screen and the path validated against are therefore provably identical.

### Interop contract (designed to need no SKIE)

Kotlin/Native's Obj-C bridge is awkward with generics, `Flow`, suspend functions and primitive arrays. The API avoids all four, so no extra Gradle plugin is required:

```kotlin
// Load path — crossed once per glyph, cached in Swift
StrokeCore.packSchemaVersion: Int
StrokeCore.loadPack(json: String): GlyphPack        // throws PackDecodeError
GlyphPack.glyph(id: String): Glyph?
Glyph.strokeCount: Int
Glyph.polyline(strokeIndex: Int): FlatPolyline      // count / x(i) / y(i) — no KotlinDoubleArray
Glyph.keyPoints(strokeIndex: Int): FlatPolyline

// Hot path — one call per touch sample, no allocation of collections
StrokeCore.newSession(glyph: Glyph, settings: TraceSettings, attempt: Int): TraceSession
TraceSession.begin(x: Double, y: Double): StrokeEvent
TraceSession.onPoint(x: Double, y: Double, tMs: Long): StrokeEvent
TraceSession.lift(): StrokeEvent
TraceSession.result(): AttemptResult?

// StrokeEvent: tag + inkS (validated arc-length) + inkX/inkY (snapped ink tip)
//              + keyPointCrossed: Int + strokeIndex: Int. Flat Doubles/Ints only.
```

Everything crossing the boundary is `Double`, `Int`, `Long`, `String`, `Boolean`, or a `data class` of those. A thin `StrokeCoreBridge.swift` wraps the exported Obj-C classes into Swift enums and `CGPoint`s so app code never sees `KotlinInt`.

### Semantic tags (engine) → Tiko copy (app)

Per the chess ADR, the engine emits tags; the app owns all child-facing language.

```txt
stroke.begin.ok          stroke.begin.wrong-place    stroke.progress
stroke.keypoint          stroke.off-path             stroke.wrong-direction
stroke.lifted-early      stroke.reset                stroke.complete
glyph.stroke-out-of-order   glyph.complete           attempt.finished
```

Tiko maps these to `write.*` i18n keys, TikoVoice utterances and haptics. Failure tags produce a soft tone and a silent ink reset — never a spoken correction.

### Tracing algorithm

1. Flatten each stroke's `d` to a polyline, adaptive subdivision, max deviation 0.25 viewBox units.
2. Build the cumulative arc-length table; normalise to `s ∈ [0,1]`.
3. Key points at `s = 0`, `s = 1`, curvature maxima above threshold, and every `keyPointSpacing` between. Author overrides win.
4. Per stroke hold `cursor` (current position) and `frontier` (furthest validated).
5. Each input point projects to `(s, distance)`. It is valid when `distance ≤ tolerance` *and* `s > cursor − backtrackSlack`.
   - Valid → advance `cursor`, raise `frontier`, emit `stroke.progress`; crossing a key point emits `stroke.keypoint` (haptic tick).
   - Invalid → apply `offPathPolicy`: `stayInPlace` (ignore), `backToLastKeyPoint` (`cursor = frontier = last crossed`), or `backToStart` (`= 0`).
6. Lifting before a key point with `allowLiftBetweenKeyPoints = false` triggers the same policy.
7. Stroke completes when `frontier ≥ 1 − ε` and every key point was crossed in order. Glyph completes when all strokes complete, in order if `strokeOrderStrict`.
8. `AttemptResult` carries mean lateral deviation, max deviation, duration, reset count, and per-stroke completion — the parent progress data.

`tolerance`, `keyPointSpacing`, `backtrackSlack`, `offPathPolicy`, `strokeOrderStrict`, `allowLiftBetweenKeyPoints` and `modelVisibility` all resolve from `TraceSettings` × attempt number, inside the engine, so iOS and Android cannot drift.

### Animation (Swift)

- **Model demo** — a dot travels the polyline at constant arc-length speed, easing per stroke, drawing a trailing line, pausing between strokes. Speed is a setting; repeat is optional.
- **Ink snapping** — ink is drawn on the corridor centreline with a small lateral lerp toward the finger (`inkSnap`, default 0.85). The child's wobble becomes a clean letter. This is the single biggest perceived-quality lever.
- **Pencil ink** — width and opacity from `force`, skew from `altitudeAngle`/`azimuth`. Finger input uses a fixed width.
- **Key point pop** — scale + fade with a `TikoFeedback.playPop()` tick.
- **Completion** — the finished glyph lifts off its guide, `TikoCelebrate` card dance, letter name/phonics spoken, one calm reward beat (glyph bounces, an emoji for that letter pops in). One variant, not five games.
- **Reduce Motion** — travel becomes a crossfade, dances become opacity pulses, matching the existing Tiko celebration path.

## TikoKotlinKit migration ladder

Measured inventory of `packages/tikokit-ios/Sources/TikoKit/` (21,232 lines total), classified by what actually blocks portability:

| Tier | Files | Lines | Platform dependency | When |
|---|---|---|---|---|
| **0 — pure** | `TikoImageURL` (40, whole file) · `TikoWordMatcherKit` (168, whole file) · `TikoMediaItem` + `TikoMediaMatcher` (~71) · `TikoVersion.isNewer` (~18) | **~297** | None for the listed units. The *rest* of those files is blocked: `TikoMediaClient` is an actor over URLSession; `TikoUpdateNotice` is `@MainActor ObservableObject` on `Bundle.main`. | **v1, with Write** |
| **1 — i18n data** | `TikoI18nGenerated` (11,126), `TikoLocales.generated`, `TikoI18n` | ~12,700 | Combine + Foundation. The generated bundle is Swift string dictionaries. | After Write ships |
| **2 — identity + API** | `TikoIdentity` | 739 | Foundation, `Security` (Keychain), OSLog. Needs `expect/actual` secure storage. | Last, own ADR |
| **never** | `TikoVoice`, `TikoSpeech`, `TikoSentence`, `TikoPopupSheets`, `TikoAppShell`, `TikoCelebrate`, `TikoChoiceGrid`, `TikoTile`, `TikoCard`, `TikoFormFields`, `TikoMediaPicker`, `TikoLogo*`, `TikoCachedRemoteImage`, `TikoColors`, `TikoOpenIcon` | ~5,800 | AVFoundation, JavaScriptCore, SwiftUI, PopupView. 17 SwiftUI views in `TikoPopupSheets` alone. | Stays Swift — this *is* the UI layer TikoKit becomes |

**Tier 0 is ~297 portable lines, not the 525 those four files total.** Two of them are mostly networking and observable-object plumbing. Counting whole files overstates the work by ~40%.

Three behavioural traps found while reading the Tier 0 sources, each now a required parity fixture rather than a note: `TikoWordMatcher.normalize` uses `lowercased(with: locale)` and Kotlin's `lowercase()` is locale-invariant — they diverge exactly on Turkish, which `packages/talk-packs/source/tr.json` shows is a supported language; `CharacterSet.punctuationCharacters`/`.symbols` have no exact Kotlin `CharCategory` equivalent at the edges; and `TikoMediaMatcher.match` depends on input iteration order for its last-write-wins collision behaviour. None would fail a smoke test; all would fail a fixture parity test. Details in the ADR.

Two notes on the tiers that matter most:

**Tier 1 is the biggest single win and it is not auth.** `TikoI18nGenerated.swift` is 11,126 lines of hand-generated Swift dictionaries — over half of TikoKit. Moving the translation *data* to a platform-neutral resource with a Kotlin resolver means the generator emits one artifact instead of per-platform Swift, and native Android inherits all 54 languages for free. Low risk (pure data, exhaustively testable by key-parity assertions against the current Swift bundle), enormous payoff.

**Tier 2 is the one that can break eleven shipped apps.** `TikoIdentity.swift` owns Keychain-backed device sessions, magic-link verification, PIN and parent/child mode. Its replacement needs Ktor plus `expect/actual` secure storage (Keychain / EncryptedSharedPreferences), and per doctrine the Swift path is deleted only after inventory, replacement, tests and smoke evidence exist. Sequencing: Write consumes the Kotlin identity client first as the only app on it; each existing app migrates individually behind its own smoke checklist; `TikoIdentity.swift` is removed last.

Per-app migration is therefore additive at every step — `TikoCore.xcframework` is a new dependency alongside TikoKit, never a replacement of it in the same commit.

## Glyph pack schema

`packages/write-glyphs/source/*.json`, schema owned by the engine (`engines/stroke/schema/glyph-pack.v1.json`), validated in CI by a Node script so pack edits don't require Gradle.

```json
{
  "packId": "print-latin",
  "packSchemaVersion": 1,
  "packVersion": 3,
  "style": "print",
  "viewBox": [0, 0, 100, 140],
  "guides": { "ascender": 10, "capHeight": 24, "xHeight": 60, "baseline": 110, "descender": 134 },
  "groups": [{ "id": "uppercase", "sortOrder": 1 }],
  "glyphs": [
    {
      "id": "upper-a", "char": "A", "groupId": "uppercase", "sortOrder": 1,
      "strokes": [
        { "d": "M50 20 L20 110", "keyPoints": [0.0, 0.5, 1.0] },
        { "d": "M50 20 L80 110" },
        { "d": "M32 78 L68 78" }
      ],
      "strokeOrderStrict": true,
      "joins": null
    }
  ]
}
```

Spoken text (letter name, phonics, example word) is **not** in the pack — it lives in `content_item_translations` and `TikoI18nWrite`, so 54 languages don't multiply the geometry. Cursive adds `joins: { entry: {x,y,angle}, exit: {x,y,angle} }` per glyph in `packSchemaVersion: 2`.

v1 packs: `shapes.json` (~10), `numbers-latin.json` (10), `print-latin.json` (52).

### Build wiring

- One Gradle build at the repo root, two subprojects. Targets: `iosArm64`, `iosSimulatorArm64`, `iosX64`, `jvm` (tests), `wasmJs` (Phase 5).
- `./gradlew assembleTikoCoreXCFramework` → `packages/tikokotlinkit/build/XCFrameworks/release/TikoCore.xcframework`, exporting both `:tikokotlinkit` and `:stroke-core`.
- `apps/write/ios/Project.yml` adds `dependencies: - framework: <path>/TikoCore.xcframework` with `embed: true`, plus a `preBuildScripts` entry that rebuilds it when stale — following the existing `generate-app-configs.mjs` pre-build guard in `apps/sum/ios/Project.yml`, and failing with `error: JDK 17+ is required to build TikoCore` rather than a cryptic linker error.
- `.github/workflows/ios-ci.yml`: new `tikocore` job on `ubuntu-latest` (`setup-java` + Gradle cache + `./gradlew jvmTest`), and `setup-java` added to the macOS jobs so the pre-build script works. Add `apps/write/ios`, `engines/stroke/**` and `packages/tikokotlinkit/**` to the trigger paths and `write`/`TikoWrite` to the app matrix.
- The XCFramework is **built, never committed** — no multi-megabyte binaries in git. The pre-build script is the only thing standing between a fresh clone and a working `xcodebuild`.
- `npm run check` gains `check-glyph-packs.mjs`, so content contributors never need the Kotlin toolchain.

## Phases

Each phase ends green on `npm run check` and, from Phase 2, `xcodebuild test`.

**Phase 0 — Contracts and toolchain, no UI.** `docs/apps/write.md` product spec. Two ADRs: the engine boundary (answering the chess-ADR implementation gate — engine path, public API name, pinning, per-platform build, saved-state schema, fixture tests, release ownership) and the TikoKotlinKit direction with the migration ladder. Glyph pack JSON Schema + `check-glyph-packs.mjs`. `packages/write-glyphs` with `shapes.json` authored by hand. Root Gradle build with both subprojects, `TikoCore.xcframework` assembling, `jvmTest` green in CI. `:tikokotlinkit` Tier 0 ported with parity tests against the Swift originals.
*Exit: shapes pack validates in CI; `TikoCore.xcframework` builds from a clean clone; both ADRs accepted. No existing app touched.*

**Phase 1 — Engine.** SVG parser, flattening, arc-length table, key point generation, the full state machine, off-path policies, difficulty × attempt resolution, scoring. JVM tests including golden replays of recorded point streams (clean trace, wobbly trace, off-path, backwards, early lift, wrong stroke order). XCFramework task wired.
*Exit: `./gradlew jvmTest` green; every fixture produces the exact expected tag sequence.*

**Phase 2 — iOS skeleton, engine on screen.** XcodeGen project, `TikoAppColor.write`, config registration, `TikoI18nWrite`. `TikoAppShell` home with `TikoChoiceGrid` groups. `TraceCanvasView` capturing coalesced touches, guide + ink + key point layers driven by `StrokeCore`, `TikoCoreBridge` and its XCTests. No audio, no celebration.
*Exit: a child can trace a circle on device and the ink only advances where the engine says it may.*

**Phase 3 — Feel.** Model demo animator, ink snapping, key point pops, haptics. TikoVoice letter name / phonics / letter sound with the sound-mode setting. TikoCelebrate on completion plus the single calm reward beat. Pencil pressure/tilt ink and Pencil-only mode. Reduce Motion, high contrast, background colour, guide line options. The five-attempt fading-help ladder.
*Exit: the tracing loop feels better than Writing Wizard on the same device, with Pencil and with a finger.*

**Phase 4 — Parent Mode and progress.** `WriteParentEditor` sheets behind the existing PIN gate: difficulty, off-path policy, guides, sound mode, left-handed, letter size, Pencil-only, which sets are enabled, model speed. `WriteProgressStore` records attempts per subject and replays them ("watch what your child traced"), synced to app-api state with the versioned envelope `{ engine: "stroke-core", engineVersion, schemaVersion, attempts }`.
*Exit: two child profiles keep independent settings and progress; a parent can replay yesterday's tracing.*

**Phase 5 — Content platform.** `0013_write_default_content.sql` seeds the packs. `/v1/write/content` serves defaults plus per-account overrides following the `getSequenceContent` pattern in `workers/content-api/src/index.ts`. `useWriteDefaults.ts` + `WriteEditor.vue`: import or draw a path, order strokes, flip direction, place key points, and preview — the preview runs the *same* engine via the `wasmJs` target, so admin and app agree exactly. iOS fetches remote packs with the bundled pack as offline fallback.
*Exit: a glyph edited in admin changes on device after relaunch; the app still works with the network off.*

**Phase 6 — Full content and release.** Complete `numbers-latin` and `print-latin`. `packSchemaVersion: 2` with join anchors, cursive engine support, `cursive-latin` pack. Release scaffolding: `apps/write/release/ios.json`, `exportOptions.plist`, App Store copy, screenshot scenes (`home`, `trace`, `celebrate`) via `TikoScreenshotMode`, entry in `release.config.json`, TestFlight.
*Exit: submitted, review-ready App Store release.*

**Phase 7 — TikoKotlinKit Tier 1, separate track after Write ships.** Move the 11,126-line generated i18n bundle to a platform-neutral resource with a Kotlin resolver; the config generator emits one artifact instead of per-platform Swift. Gated by key-parity tests asserting every key/locale pair resolves identically to the current Swift bundle. Write migrates first as the only consumer; existing apps follow one at a time.
*Exit: Write resolves all 54 languages through Kotlin; `TikoI18nGenerated.swift` deleted only once every app is migrated and smoke-checked.*

**Later, not v1:** TikoKotlinKit Tier 2 (identity + API clients via Ktor with `expect/actual` secure storage, own ADR, per-app migration) · words and sight-word lists with letter joins · caregiver audio recording per glyph · printable PDF worksheets · non-Latin packs (the engine is script-agnostic; Japanese kana and Arabic are content) · native Android on the same engine · repo-wide open-source decision.

## Verification

**Engine (the real safety net).** `./gradlew jvmTest` from the repo root. Fixture replays assert exact tag sequences for clean, wobbly, off-path, reversed, early-lift and out-of-order traces at each difficulty × attempt combination. Property tests assert `pointAt(closestPoint(p).s)` is within tolerance for random points near random paths, and that a perfect replay of `polyline` always completes.

**TikoKotlinKit parity.** Every tier is gated by tests asserting the Kotlin implementation returns byte-identical results to the Swift original for a shared fixture set — CDN URL construction, word-matcher inputs, media query strings, version comparisons, and from Phase 7 every i18n key/locale pair. A tier is not "done" because it compiles; it is done when parity holds.

**Bridge and app.** `cd apps/write/ios && xcodegen generate && xcodebuild test -scheme TikoWrite -destination 'platform=iOS Simulator,name=iPhone 16'`. XCTests cover `TikoCoreBridge` (no `KotlinInt` leaks, polyline round-trips), `WriteGlyphStore` (remote pack overrides bundled, offline falls back), `WriteSettingsStore`/`WriteProgressStore` per-subject isolation, and `TraceViewModel` tag→copy mapping. XCUITests: launch, open a shape, trace it to completion, celebration appears, Parent Mode opens behind the PIN.

**Toolchain from cold.** The real regression risk is a repo that no longer builds without Java. Verify from a clean clone with no Gradle cache: `npm ci && ./gradlew assembleTikoCoreXCFramework && cd apps/write/ios && xcodegen generate && xcodebuild build -scheme TikoWrite`. Then confirm the eleven existing iOS apps still build with no Gradle involvement at all — nothing outside `apps/write/ios` may acquire a Kotlin dependency in v1.

**Content.** `npm run check` gates pack schema. `node tools/check-glyph-packs.mjs --strict` additionally asserts every stroke's key points are monotonic in `s` and every glyph has a `char` and `groupId`.

**Cross-platform agreement.** The same fixture files under `engines/stroke/src/commonTest/resources/fixtures/` are replayed by the JVM suite, by an XCTest in `apps/write/ios/Tests/`, and (Phase 5) by a Vitest suite against the `wasmJs` build. Divergence is a test failure, not a bug report.

**On device.** Real iPad with Apple Pencil for latency, pressure and palm rejection — the simulator cannot prove Phase 3. Then `--screenshot-mode` scenes for the release shots.

- **Repo-wide open source.** Requires a secrets/wrangler audit across every worker before the monorepo could go public. `engines/stroke` and `packages/write-glyphs` are structured to extract cleanly either way; decide before the App Store release.
- **Glyph authoring effort.** 52 print glyphs × stroke order, direction and key points is the largest hand-authoring task in the plan. Phase 1's engine tests only need shapes, so authoring can run in parallel with Phases 2–4 rather than blocking them.
- **Handwriting style choice.** One Tiko print style in v1. Which convention it follows (single-storey `a`, entry strokes, `4` open or closed) is a pedagogical call worth making explicitly in `docs/apps/write.md` — it is what parents notice first.
- **Kotlin toolchain cost.** This adds a JDK and Gradle to a repo that is npm + XcodeGen + wrangler. Contributors touching only glyph content are shielded (`check-glyph-packs.mjs` is Node), but anyone building the iOS app needs Java 17+. Accepted deliberately for the Android and admin-preview payoff; worth revisiting if `wasmJs` turns out not to serve the admin preview cleanly, since that removes one of the three justifications.
- **Tier 2 secure storage.** Keychain and EncryptedSharedPreferences have genuinely different semantics around access groups, biometric gating and backup behaviour. The `expect/actual` boundary needs designing against Tiko's device-first session model before Tier 2 starts, not during it.
