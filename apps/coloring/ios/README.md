# Tiko Coloring — iOS

A native SwiftUI app over the Kotlin Multiplatform `ColoringCore` engine. Kotlin owns
the document, hit testing, fills and history; Swift owns rendering, gestures and the
interface.

## Build and run

The project is generated by XcodeGen — **never hand-edit `TikoColoring.xcodeproj`**,
edit `Project.yml` and regenerate:

```bash
cd apps/coloring/ios
xcodegen generate
```

The app links `ColoringCore.xcframework`. A pre-build script builds it if missing, but
you can build it yourself:

```bash
cd engines/coloring
JAVA_HOME=/opt/homebrew/opt/openjdk@21 \
  gradle :coloring-core:assembleColoringCoreReleaseXCFramework
```

Then build for a device or simulator:

```bash
cd apps/coloring/ios
xcodebuild -project TikoColoring.xcodeproj -scheme TikoColoring \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' test
```

Verified running on a physical iPhone (arm64) and on the simulator.

## Layout

```
Sources/
  TikoColoringApp.swift        @main, hands off to the library
  Models/
    ColoringPage.swift         a bundled page and its artwork
    ColoringSession.swift      owns one ColoringEngine, republishes its snapshot
  Views/
    ColoringLibraryView.swift  page picker with outline thumbnails
    ColoringView.swift         the colouring screen
  Support/
    ColoringSnapshot.swift     read model for snapshotJson(), canvas transform, hex colour
  Resources/Pages/*.svg        the bundled coloring pages
```

`ColoringSession` holds no copy of the document — every edit goes through the engine
and the view renders the snapshot that comes back, so there is one source of truth.

## Adding a coloring page

1. Add an SVG to `Sources/Resources/Pages/` that satisfies the importer contract in
   [`engines/coloring/README.md`](../../../engines/coloring/README.md): polygons only
   (`M`, `L`, `H`, `V`, `Z`), one region per `<path>`, every path closed, unique ids.
2. Add a `ColoringPage` entry in `Models/ColoringPage.swift`.
3. Run the tests. `ColoringPageTests` imports every bundled page, so a malformed one
   fails there rather than crashing on a child's device — which matters because the
   engine throws on unimportable artwork by design.

## Not built yet

- `TikoAppConfig.coloring` and TikoKit integration. The config generator in
  `tools/generate-app-configs.mjs` has no `coloring` entry, so the app currently does
  without shared Tiko theming and identity, and carries no keychain entitlement.
- Persistence. Colouring is lost when a page is closed; the engine can already
  `serialize()`, so this is storage plumbing rather than engine work.
- Brush, eraser, pan and zoom — the engine's next slice.
- Custom pages from the media library or the generation pipeline.
- Path caching, so snapshots are not reparsed on every render.
